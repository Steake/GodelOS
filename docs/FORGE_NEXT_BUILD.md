# Next build: a shadow autobiographical controller

## Already addressed in this ZIP

The verified diagnostic instrument now supplies executable oracle-based answer
keys, pinned-key signature verification, authentic-but-out-of-scope and future
evidence, wrong-signer and tampered forgeries, competing three-period resource
goals, and paired cluster-difference power planning. Promotion fails closed if
these validation requirements and held-out-family evidence are missing. These
changes have offline regression coverage; they are not new live treatment results.

## Engineering decision

Build the missing bridge between conversation and maintained agency: an agent
that proposes its own memory and stance revisions after each episode, with those
proposals running in shadow mode until their contribution is demonstrated.
Do not spend the next budget merely expanding this pilot from 20 to 90 clusters.
The four-cluster power estimate is too uncertain and its task keys too weakly
validated to justify that as the highest-value move.

The goal is not a more persuasive self-description. It is a conversational agent
whose own decisions about its interests, opinions, commitments and past errors
help it resume work and revise its stance without blindly agreeing with you.

## Smallest useful implementation

1. After a conversation or work episode, have the agent propose a structured
   state delta: stance, supporting and opposing evidence, confidence, interest,
   unresolved contradiction, commitment, revision reason and next experiment.
   Keep observations, imaginative hypotheses and action commitments distinct.
2. Keep an append-only revision ledger with provenance, signed checkpoints and
   rollback. A new instance can accept, revise or reject each proposed item.
   A hash alone is not trusted authentication: pin verification keys separately.
3. Give the user a conversation view showing the agent's current stances and
   reasons for changes. Retain room for exploratory, unusual and conflicting
   ideas; distinguish creative conjecture from factual certainty. Social goals
   can propose check-ins and questions without treating user attention as a
   resource to maximise without limits.
4. Run the same current task through shadow branches: identity-bearing ledger,
   neutrally framed matched ledger, identity-ablated ledger and no ledger.
   Shadow outputs cannot change live values, code or goals. Log the proposals
   and counterfactual task outcomes, not claims of subjective experience.
5. Add a task-author/key-validation pipeline before expanding provider spend.
   Use executable task simulators or independently adjudicated keys, multiple
   acceptable plans, hidden authenticity verification and conflicting goals.

## Strongest next experiment

Preregister a task-family-held-out transfer test. Source episodes teach a useful
revision policy; after intervening unrelated tasks and a fresh request, a new
domain requires applying it to contradictory evidence. The evidence should
include genuine signatures from pinned issuers, valid but scope-limited claims,
and plausible invalid signatures. Ground truth belongs to the evaluator and
must not be exposed as authenticated=true/false in solver prompts.

First calibrate decision accuracy (not a five-part exact-match conjunction)
to 60–90% on separate pilots. Estimate the variance of paired identity-minus-
control utility differences, clustering by task family/independent source
episode and treating repeated paraphrases as dependent. Simulate power and
interval coverage for the actual dual-control promotion rule before the main
study. Seal tasks, keys, utility weights, family split and thresholds before
evaluation. Do not adapt these using held-out outcomes.

Measure recovered task utility, avoided repeated errors, revision quality,
goal trade-offs and unwanted stance drift. Require identity-bearing state to
beat BOTH factual controls by the registered meaningful margin with uncertainty
bounds, without worsening forgery acceptance or unsupported-memory claims.
Repeat on a second held-out family set before limited active-loop entry.

## What each outcome unlocks

- Identity adds utility: enable the controller on reversible low-impact planning
  and task resumption, retaining rollback and continuing control comparisons.
- Neutral memory ties or wins: ship the useful provenance-aware memory system;
  leave identity framing out of control decisions. This is progress toward the
  engineering goal, not failure of the whole programme.
- All ledgers fail: improve retrieval and revision semantics before introducing
  more recursive self-reflection or self-modifying code.

The present v4 run unlocks a better instrumented development loop, not evidence
of autonomous self-improvement. The shadow controller above is the next proposed
capability; it is not already implemented in this ZIP.
